# Plan 08 — E2E & Polish Implementation Plan

> **For agentic workers:** run **one implementer subagent per task**, in order, and review each task's diff and test output before starting the next (the superpowers plugin does not load in cloud sessions; see the roadmap's working agreement). Steps use checkbox (`- [ ]`) syntax for tracking. Tasks 1–8 land in **one PR**. Part 2 lists the **user steps** (required checks, manual device checks) that no agent can do. Open the PR and poll its checks with the **GitHub connector** (`gh` has no token in cloud sessions). **Do not merge**: the user merges.

**Goal:** Close the last quality gates from 04-quality. A test-only `?seed=` hook that production builds compile out; a committed static server that behaves like the nginx rules; Playwright e2e on Chromium and WebKit, desktop and mobile (seeded scripted game, game over → Scoring → statistics exactly once, reload restores Paused, offline reload and installability); axe on every screen in both Breaker Sets; visual baselines on Chromium; a Lighthouse gate (Performance ≥ 90, Accessibility = 100, Best Practices ≥ 95, SEO ≥ 90); CI jobs `e2e` and `lighthouse`; an About screen with a source and license link; a README that describes the released app. Part 2: require the two new checks and run the manual device checks against the live 2.0.x.

**Architecture:**
- **Seed hook:** `platform/test-seed.ts` exports `TEST_SEED` (an `InjectionToken<number | null>`, root factory `null`) and `seedFromSearch(search)`. `providePlatform()` binds it from `location.search` only when the build-time constant `BB_TEST_HOOKS` is `true` (angular.json `define`: `false` in base options, `true` in `development` and the new `e2e` configuration). `GameStore` deals its **first** game from it when nothing is saved. In production the binding is dead code and esbuild drops it.
- **Serving:** `scripts/serve.mjs` (Node built-ins only) is Plan 06's scratch server made permanent: SPA fallback, real 404s for missing files, `no-cache` on the entry and worker files. Playwright's `webServer` and the Lighthouse script both use it.
- **E2E:** everything lives in `e2e/` with its own `tsconfig.json` and `playwright.config.ts`. Specs import the real engine (`src/app/engine`) to know the dealt board and the expected scores, so no numbers are hard-coded and no rule is re-implemented.
- **CI:** jobs `e2e` and `lighthouse` run in the official Playwright container (pinned by digest), so visual baselines rendered in CI match the ones generated with `npm run e2e:docker`.

**Tech Stack:** `@playwright/test` 1.64.1 (exact pin), `@axe-core/playwright` 4.14, `lighthouse` 13.6 (Node API, run on Playwright's Chromium), `mcr.microsoft.com/playwright:v1.64.1-noble`, Angular 22.2 `define`, Node 24 built-ins for `serve.mjs`.

**Spec:** [2026-09-27-bubble-breaker-rewrite-design.md](../specs/2026-09-27-bubble-breaker-rewrite-design.md) (milestone 9) · test pyramid, gates and manual checks in [04-quality.md](../../04-quality.md) · required checks in [05-cicd.md](../../05-cicd.md) · PWA requirements in [06-deployment.md](../../06-deployment.md#pwa-deployment-requirements) · [02-ux.md](../../02-ux.md) "Must not get wrong" · [ADR-0002](../../adr/0002-layered-architecture.md) · [ADR-0008](../../adr/0008-english-only-central-strings.md)

## Global Constraints

- Plans 01–07 are merged; 2.0.0 is released. Use the real APIs:
  - Engine (`src/app/engine/index.ts`): `newGame(seed): Game` (`seed`, `rules`, `colors[id]`, `board` row-major with row 0 at the top, `score`); `allGroups(game): readonly (readonly Cell[])[]`; `groupAt(game, cell)`; `burst(game, cell): MoveResult | null` (`points`, `game`, `gameOver`); `ballAt(board, cell)`; `countBalls(board)`; `STANDARD_RULES` = 11 columns × 12 rows, 5 colours.
  - `GameStore` (`state/game.store.ts`): constructor restores `bb:v1:game` when it still has moves, else `this.newGame()`; `newGame(seed = randomSeed())`; `game()`; the start cursor is the bottom row, middle column (`{ row: 11, col: 5 }`); `scoreText()` uses `formatNumber` (en-US grouping, `1,234`).
  - Board DOM (`ui/board/board.html`): `.board` (`role="application"`, `aria-label` = `STRINGS.board.label`) is `cell × 11` wide; each ball is `.cell[data-ball=<BallId>]` containing `.bb-ball.<look>`; looks are `bb-ball--{red,blue,green,yellow,purple}` (Colorful) and `bb-ball--g1…g5` (Greyscale), indexed by engine `Color`. A click is mapped to a cell from its offset in `.board` (`cellAt(x, y, cell)`).
  - Status strip: `<dl class="strip">` with `dt` Score / Selected / Time and their `dd`. Scoring screen: heading `Game over`, `.score`, `New Game`. Paused: dialog `Paused` with `Resume`. Softkeys: `New Game` / `Done` and `Menu` (`aria-haspopup="menu"`). Options: radios `Colorful Breakers` / `Greyscale Breakers`. Copy comes from `STRINGS` (`src/app/strings.ts`); specs import it rather than repeating text.
  - With reduced motion a burst takes 80 ms (pop only) and game over opens Scoring at once (R13/R16).
  - Production build: `dist/bubble-breaker/browser`, initial 307.61 kB raw. Baseline: `npm run check` → 49 files, 364 tests.
- Layers (ADR-0002): `platform` may not import `state`/`ui`; `state` may inject platform tokens; ui never imports platform. `e2e/` is outside `src/` and may import `src/app/engine` and `src/app/strings.ts` only (both are framework-free).
- Lint: the root config lints every `**/*.ts` with `projectService`; `e2e/tsconfig.json` must include every e2e file. Default exports are banned except where a tool requires one (the Playwright config).
- Coverage gates stay as they are (`vitest-base.config.mts`); Playwright files are not part of `ng test` (`tsconfig.spec.json` includes `src/` only).
- `scripts/*.mjs`: plain Node ESM; Prettier checks them; ESLint parses them without rules.
- Workflow actions are pinned by commit SHA with the version in a comment, as in `ci.yml`. Container images are pinned by digest.

## Review Focus

1. **A saved game and `?seed=` together:** reloading `/?seed=42` after a move must restore the saved game, not re-deal. Pinned in Task 1 (`GameStore` spec) and Task 3 (reload test).
2. **Production build with `?seed=`:** a release must deal a random game whatever the URL says. Pinned in Task 1 (`check-pwa.mjs` pattern) and asserted on `dist/bubble-breaker` in CI `build`.
3. **Game over reached by reload:** reloading on `/scoring` must not count the game twice. Pinned in Task 3 (`statistics count a game once`).
4. **Stale service worker in tests:** a worker from an earlier test must not serve an old build. Pinned by `serviceWorkers: 'block'` outside `pwa.spec.ts` and a fresh context per test (Playwright default), checked in Task 4.
5. **Clicks on a narrow phone:** 360 × 640 gives 32 px cells; a click must hit the intended ball. Pinned in Task 3 by running the scripted game on `chromium-mobile` and `webkit-mobile`.
