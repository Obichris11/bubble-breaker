# Plan 04 — Board UI Implementation Plan

> **For agentic workers:** run **one implementer subagent per task**, in order, and review each task's diff and test output before starting the next (the superpowers plugin does not load in cloud sessions; see the roadmap's working agreement). Steps use checkbox (`- [ ]`) syntax for tracking. Open the PR and poll its checks with the **GitHub connector** (`gh` has no token in cloud sessions). **Do not merge**: the user merges.

**Goal:** Render the game board from the Plan 03 signals and make it playable by pointer and keyboard: whole-pixel layout math, balls keyed by stable id, group highlight, points bubble, keyboard focus cursor, polite live region and the pop → fall → slide animations, with `src/app/ui/**` coverage ≥ 80 %. The title bar stays as it is; status strip, softkeys, menus, dialogs and routes are Plan 05.

**Architecture:** One new folder, `src/app/ui/board/`, under the lint-enforced layer rule (ADR-0002): ui imports `state` and engine **types** only.
- Pure helpers, unit-tested without TestBed: `board-layout.ts` (cell size, hit testing, bubble placement), `ball-look.ts` (tokens.css classes, shape hints, spoken names) and `announcer.ts` (live-region texts from a before/after snapshot of the store).
- Components (standalone, `OnPush`, signal inputs):
  - `GameBoard` (`bb-board`) renders the highlight, balls, focus ring and points bubble from `GameStore`/`SettingsStore` signals and turns clicks and keys into `GameStore` intents.
  - `BoardArea` (`bb-board-area`) measures the white area with a `ResizeObserver`, feeds the `cell` input and treats taps beside the board as "outside".
  - `PointsBubble` and `LiveRegion` are small presentational components.
- Animations are CSS transitions on `transform`/`opacity`, switched by phase classes (`board--fall`, `board--slide`, `cell--popping`) whose durations and easings are the `--bb-dur-*`/`--bb-ease-*` tokens. The PhaseRunner (Plan 03) decides *when* a phase starts; CSS only interpolates. Reduced motion comes from the tokens' own media query.
- Until Plan 05 adds the Game screen route, the App shell mounts `<bb-board-area>` directly in `<main>`.
- Two small state changes come first: game over clears `paused` (PR #8 review), and `GameStore.cursorGroup` gives the ui the group under the cursor without importing engine functions.

**Tech Stack:** Angular 22.2 standalone components, signals (`input`, `computed`, `effect`, `viewChild`), `afterNextRender`, `ResizeObserver`; CSS custom properties from `tokens.css`; Vitest 5 via `ng test` with `@testing-library/angular` 19 on jsdom.

**Spec:** [2026-09-27-bubble-breaker-rewrite-design.md](../specs/2026-09-27-bubble-breaker-rewrite-design.md) (milestone 4) · layout, interaction, motion and a11y in [02-ux.md](../../02-ux.md) and the [handoff](../../design/Handoff.dc.html) · board and ball in [03-architecture.md](../../03-architecture.md#ui) · gates in [04-quality.md](../../04-quality.md#gates) · [ADR-0002](../../adr/0002-layered-architecture.md) · [ADR-0003](../../adr/0003-dom-rendering.md) · [ADR-0008](../../adr/0008-english-only-central-strings.md)

## Global Constraints

- Plans 01–03 are merged. Use the real APIs:
  - `GameStore` (`src/app/state/game.store.ts`): `gameId`, `game`, `selection` (`{ cells, anchor }`), `phase`, `positions` (`ReadonlyMap<BallId, Cell>`, lags `game().board` during a burst), `popping`, `cursor`, `paused`, `selectedPoints`, `canInteract`; intents `tap(cell)`, `newGame(seed?)`, `moveCursor(direction)`, `activateCursor()`, `clearSelection()`. `tap` already ignores input while `canInteract()` is false and treats off-board cells as "outside" (clears the selection).
  - `SettingsStore`: `breakerSet()` (`'colorful' | 'greyscale'`), `shapeHints()`.
  - `formatNumber` from `state/format.ts`; `BreakerSet` from `state/persistence.ts`; `STRINGS` from `src/app/strings.ts`.
  - Test helpers: `createFakePlatform()` (`platform/testing/fakes.ts`), `recordFrom()` (`state/testing/records.ts`, ball id = cell index), `gameFrom()` (`engine/testing/fixtures.ts`).
- Layers: production files under `src/app/ui/` import `state`, `strings.ts` and engine **types** (`import type`) only; never `platform`. Task 5 exempts ui `*.spec.ts` files from that rule so specs can use engine fixtures and the platform fakes.
- Components: standalone, `ChangeDetectionStrategy.OnPush`, selector prefix `bb-`, signal `input()`s, `inject()`. File names without a `.component` suffix, like `app.ts`. No RxJS.
- Animate `transform` and `opacity` only. Durations and easings come from the `--bb-dur-*`/`--bb-ease-*` tokens; never hard-code a duration in component CSS. Ball nodes are keyed by `BallId` and rendered in id order, so they are never moved or re-created between phases.
- Do not edit `src/styles/tokens.css` (verbatim copy of the design tokens). Board-only styles go into component CSS.
- All user-visible text, including live-region announcements, lives in `src/app/strings.ts` (ADR-0008).
- Component specs use Testing Library queries by role, name or text where they exist; balls are found by their `data-ball` attribute, the focus ring by `data-testid`. After a signal change outside an event handler, call `fixture.detectChanges()`; move time with `platform.clock.advance(ms)`.
- Coverage: `src/app/ui/**` ≥ 80 %, `src/app/state/**` stays ≥ 90 %, `src/app/engine/**` ≥ 95 %, overall ≥ 80 % (lines, statements, functions, branches).
- Lint bans `any`, non-null assertions outside specs and `testing/`, default exports, and `console.*` other than `warn`/`error`. Template accessibility rules are on.

## Decisions this plan makes

The docs leave these points open or disagree. Task 10 writes them back into `02-ux.md`, `03-architecture.md`, `04-quality.md` and the spec.

| Topic | Decision | Why |
|---|---|---|
| Paused at game over | `GameStore.finish()` clears `paused` before it stops the timer | PR #8 review: a pause during the final burst (phase pop/fall/slide) survived into Scoring. Clearing it at the one place every game over passes is simpler than guarding `pause()` per phase |
| Cursor group | New `GameStore.cursorGroup` (`computed`, `[]` on an empty cell or a lone ball) | The live region says "group of 6", but ui may not call the engine's `groupAt` (lint) |
| Where the board lives until Plan 05 | `App` renders `<bb-board-area>` inside `<main>`, before `<router-outlet>`; Plan 05 moves it into the Game screen at route `''` | Routes are Plan 05, but the board must be visible and testable now |
| Paused before Plan 05 | No Paused UI yet. A paused board ignores taps and Enter (`canInteract`); **N** still starts a new game | The dialog is Plan 05 |
| **M** key | Not handled here; Plan 05 binds it with the menu | The menu is Plan 05 |
| Component names | `GameBoard` (`board.ts`, `bb-board`), `BoardArea` (`board-area.ts`), `PointsBubble`, `LiveRegion`; helpers `board-layout.ts`, `ball-look.ts`, `announcer.ts` | `Board` would clash with the engine type; file names follow `app.ts` |
| Measuring | `BoardArea` observes its own content box; its padding (`0 4px 4px`) is CSS, so the handoff formula's `− 2 × 4` and `− 4` are already applied. `cell_max` is read from the computed `--bb-cell-max` token (72 px, 48 px under `pointer: fine`), falling back to 72. No minimum cell | tokens.css already switches `cell_max` per pointer type; one source of truth |
| Hit testing | One `click` handler on the board: `cellAt(x − left, y − top, cell)`. Points beside the board give off-board cells, which `GameStore.tap` treats as "outside". A click on the free area of `BoardArea` taps `OFF_BOARD` | 02-ux: one pointer handler, whole cell is the hit area; `click` covers mouse, touch and pen and needs no drag handling |
| Pointer vs. cursor | A pointer tap does not move the keyboard cursor; it hides the focus ring until the next key press or keyboard focus | `GameStore` has no "set cursor" intent; the prototype moves it, but the ring is hidden after a tap anyway |
| Focus ring visibility | An explicit keyboard flag (set by `keydown` and non-pointer `focus`, cleared by `pointerdown`) instead of the `:focus-visible` selector | Deterministic and testable in jsdom; same behaviour as the prototype's `kbd && focused` |
| Ball DOM | Balls render in `BallId` order from `positions()`. Popped balls leave the DOM when the fall frame starts (after their 160 ms pop) | Re-ordering `@for` items moves DOM nodes, which restarts their transitions; at most 132 nodes |
| Highlight during pop | The highlight is the selection's cells plus the cells of popping balls (the store clears the selection when the burst starts) | Handoff motion table: "highlight stays behind it" |
| Select motion | Only the points bubble fades in (80 ms CSS animation on creation); the highlight appears instantly. Moving the selection keeps the bubble node, so it jumps without a fade | Handoff motion table; 02-ux's "Highlight + bubble fade in" is read as one row for both |
| Bubble text and a11y | `"N points"` (always plural: a group of 2 is worth 2). `aria-hidden`, `pointer-events: none` | The live region and the Selected field (Plan 05) repeat the value |
| Shape hints | A child `<span aria-hidden>` with ▲ ● ■ ◆ ✚ at `0.36 × cell`, white 80 % (yellow: black 50 %), only on Colorful | Values from the prototype; not in tokens.css, which stays verbatim |
| Reduced-motion pop | Opacity only: the scale transform is dropped under `prefers-reduced-motion` | tokens.css and 02-ux: "Opacity 80 ms linear" |
| Live-region texts | Cursor: "Row 4, column 7, blue, group of 6" / "…, red, no group" / "Row 1, column 1, empty". Selection: "6 blue balls selected, 30 points. Press Enter again to burst." Burst: "+30, score 1,234". Clear: "Selection cleared." New game: "New game." Game over: "Game over. No groups left. Score 1,234." Rows and columns count from 1, top left | The handoff gives examples, not a full list |
| What is announced | After each pointer or keyboard input, the first match of: new game → burst → new selection → cleared selection → cursor move; nothing if nothing changed. Game over is announced by an effect when `phase` becomes `over` | One message per input keeps the polite region short |
| Greyscale names | diagonal, solid, dotted, banded, checkered | 02-ux and the Component Sheet; the Game Screen prototype says "striped" |
| Board label | "Bubble Breaker board, 11 columns by 12 rows. Arrow keys move, Enter or Space selects and bursts, Escape clears, N starts a new game." | The prototype's label omits Space and N |
| ui spec imports | ui `*.spec.ts` files are exempt from the ui import rule | Specs need engine fixtures and `createFakePlatform()`; production ui code keeps the rule |
| ui coverage gate | `src/app/ui/**` ≥ 80 % in all four metrics, enforced in `vitest-base.config.mts` | Roadmap/user request; mirrors the engine and state gates |

```ts
import type { Board, Cell } from '../../engine';

/** Chrome heights and board padding from 02-ux "Screen layout" (px). */
export const CHROME = {
  titleBar: 26,
  statusStrip: 30,
  softkeysTouch: 44,
  softkeysFine: 32,
  boardSidePad: 4,
  boardBottomPad: 4,
} as const;

/** `--bb-cell-max` on touch screens; `pointer: fine` lowers it to 48 px in tokens.css. */
export const CELL_MAX_TOUCH = 72;

/** Minimum distance of the points bubble's centre from the board's left and right edges. */
export const BUBBLE_EDGE = 34;

/** A cell left of and above the board: `GameStore.tap` treats it as "outside", which clears. */
export const OFF_BOARD: Cell = { row: -1, col: -1 };

export type Grid = Pick<Board, 'columns' | 'rows'>;

export interface Size {
  readonly width: number;
  readonly height: number;
}

export interface BubblePlacement {
  /** Centre of the bubble, board coordinates (px). */
  readonly x: number;
  /** Bottom edge of the bubble (above the anchor) or its top edge (`below`). */
  readonly y: number;
  /** True for an anchor in the top row: the bubble hangs below the ball. */
  readonly below: boolean;
}

/** Space left for the board in a viewport once the chrome and the board padding are taken. */
export function availableSpace(viewport: Size, softkeys: number): Size {
  return {
    width: viewport.width - 2 * CHROME.boardSidePad,
    height:
      viewport.height - CHROME.titleBar - CHROME.statusStrip - softkeys - CHROME.boardBottomPad,
  };
}

/** Handoff §1: the largest whole-pixel cell that fits `space`, capped at `cellMax`. */
export function cellSize(space: Size, grid: Grid, cellMax: number): number {
  const fit = Math.min(space.width / grid.columns, space.height / grid.rows, cellMax);
  return Math.max(0, Math.floor(fit));
}

/** Reads `--bb-cell-max` ("72px"); falls back to the touch value when it is missing. */
export function parseCellMax(value: string): number {
  const parsed = Number.parseFloat(value);
  return Number.isFinite(parsed) && parsed > 0 ? parsed : CELL_MAX_TOUCH;
}

/** The cell under a point in board coordinates. Points off the board give off-board cells. */
export function cellAt(x: number, y: number, cell: number): Cell {
  if (cell <= 0) {
    return OFF_BOARD;
  }
  return { row: Math.floor(y / cell), col: Math.floor(x / cell) };
}

/** `translate()` that places a cell-sized element on `at`. */
export function translate(at: Cell, cell: number): string {
  return `translate(${String(at.col * cell)}px, ${String(at.row * cell)}px)`;
}

/** Handoff §2: above the tapped ball (below it in the top row), centre clamped 34 px from the edges. */
export function bubblePlacement(anchor: Cell, cell: number, grid: Grid): BubblePlacement {
  const centre = anchor.col * cell + cell / 2;
  const x = Math.min(Math.max(centre, BUBBLE_EDGE), grid.columns * cell - BUBBLE_EDGE);
  const below = anchor.row === 0;
  return { x, y: below ? cell + 2 : anchor.row * cell - 2, below };
}
```

```ts
import type { Cell, Game } from '../../engine';
import { formatNumber } from '../../state/format';
import type { Selection } from '../../state/game.store';
import type { BreakerSet } from '../../state/persistence';
import { STRINGS } from '../../strings';
import { colorName } from './ball-look';

/** The parts of `GameStore` the live region reports on, read before and after an input. */
export interface BoardSnapshot {
  readonly gameId: string;
  readonly game: Game;
  readonly selection: Selection | null;
  readonly cursor: Cell;
  /** `GameStore.cursorGroup().length`. */
  readonly cursorGroupSize: number;
}

function nameAt(game: Game, cell: Cell, set: BreakerSet): string | null {
  const id = game.board.cells[cell.row * game.board.columns + cell.col] ?? null;
  const color = id === null ? undefined : game.colors[id];
  return color === undefined ? null : colorName(color, set);
}

/** "Row 4, column 7, blue, group of 6": rows and columns count from 1, top left. */
export function cursorText(snapshot: BoardSnapshot, set: BreakerSet): string {
  const { cursor } = snapshot;
  const name = nameAt(snapshot.game, cursor, set);
  return name === null
    ? STRINGS.board.cursorEmpty(cursor.row + 1, cursor.col + 1)
    : STRINGS.board.cursorBall(cursor.row + 1, cursor.col + 1, name, snapshot.cursorGroupSize);
}

/** "6 blue balls selected, 30 points. Press Enter again to burst." */
export function selectionText(game: Game, selection: Selection, set: BreakerSet): string {
  const size = selection.cells.length;
  return STRINGS.board.selected(
    size,
    nameAt(game, selection.anchor, set) ?? '',
    formatNumber(size * (size - 1)),
  );
}

export function gameOverText(score: number): string {
  return STRINGS.board.gameOver(formatNumber(score));
}

/**
 * What the live region says after one pointer or keyboard input, or null when nothing worth
 * announcing changed. The first matching change wins: new game, burst, selection, cleared
 * selection, cursor move.
 */
export function announcement(
  before: BoardSnapshot,
  after: BoardSnapshot,
  set: BreakerSet,
): string | null {
  if (after.gameId !== before.gameId) {
    return STRINGS.board.newGame;
  }
  const gained = after.game.score - before.game.score;
  if (gained > 0) {
    return STRINGS.board.burst(formatNumber(gained), formatNumber(after.game.score));
  }
  if (after.selection !== null && after.selection !== before.selection) {
    return selectionText(after.game, after.selection, set);
  }
  if (after.selection === null && before.selection !== null) {
    return STRINGS.board.cleared;
  }
  if (after.cursor.row !== before.cursor.row || after.cursor.col !== before.cursor.col) {
    return cursorText(after, set);
  }
  return null;
}
```

**Interfaces:**

- Produces: `GameBoard` (`bb-board`) with `cell = input.required<number>()`. The board element is `role="application"`, `tabindex="0"`, labelled by `STRINGS.board.label`, sized `11·cell × 12·cell`, and sets `--bb-cell` for its children. Stacking (tokens): highlight `.spot` (z1) → ball `.cell` (z2) → focus `.ring` (z3, Task 8) → points bubble (z4).

How the animation works:
- Each ball is a `.cell` wrapper placed with `translate(col·cell, row·cell)` and an inner `.bb-ball` with the tokens.css recipe class. The idle ball never changes; highlight and ring are separate elements behind and above it (handoff §7.4).
- `phase()` adds `board--fall` or `board--slide` to the board. Those classes give the `.cell` wrappers a `transform` transition with the matching tokens, so when `positions()` changes at the start of a frame, the balls glide to their new cells. Outside those phases a position change (new game, restore) jumps.
- `cell--popping` scales the inner ball to 0.2 and fades it out over `--bb-dur-pop`. The transition sits on the popping state only, so a new game never fades balls back in. Under `prefers-reduced-motion` only the opacity fades (the tokens already shorten the pop to 80 ms linear and zero the other durations).
- Balls are listed in `BallId` order and tracked by id. The PhaseRunner keeps the old board during `pop`, so popping balls stay in place behind their highlight; they leave the DOM at the fall frame.

```ts
    this.focused.set(false);

    const before = this.snapshot();
    intent();
    const text = announcement(before, this.snapshot(), this.settings.breakerSet());
    if (text !== null) {
      this.message.set(text);
    }

    return {
      gameId: this.store.gameId(),
      game: this.store.game(),
      selection: this.store.selection(),
      cursor: this.store.cursor(),
      cursorGroupSize: this.store.cursorGroup().length,
    };
  }
```

```ts
import {
  afterNextRender,
  ChangeDetectionStrategy,
  Component,
  DestroyRef,
  ElementRef,
  inject,
  signal,
} from '@angular/core';
import { GameStore } from '../../state/game.store';
import { GameBoard } from './board';
import { cellSize, OFF_BOARD, parseCellMax } from './board-layout';

/**
 * The white area between the status strip and the softkeys. It measures itself with a
 * ResizeObserver, derives the whole-pixel cell size and bottom-aligns the board. A tap on the
 * free space around the board counts as "outside the board" (rule R9: clears the selection).
 */
@Component({
  selector: 'bb-board-area',
  imports: [GameBoard],
  template: '<bb-board [cell]="cell()" />',
  styleUrl: './board-area.css',
  changeDetection: ChangeDetectionStrategy.OnPush,
  host: { '(click)': 'onClick($event)' },
})
export class BoardArea {
  private readonly host = inject<ElementRef<HTMLElement>>(ElementRef);
  private readonly destroyRef = inject(DestroyRef);
  private readonly store = inject(GameStore);
  protected readonly cell = signal(0);

  constructor() {
    afterNextRender(() => {
      if (typeof ResizeObserver === 'undefined') {
        return;
      }
      const element = this.host.nativeElement;
      const observer = new ResizeObserver((entries) => {
        for (const entry of entries) {
          const cellMax = parseCellMax(getComputedStyle(element).getPropertyValue('--bb-cell-max'));
          this.cell.set(cellSize(entry.contentRect, this.store.game().board, cellMax));
        }
      });
      observer.observe(element);
      this.destroyRef.onDestroy(() => {
        observer.disconnect();
      });
    });
  }

  protected onClick(event: MouseEvent): void {
    if (event.target === this.host.nativeElement) {
      this.store.tap(OFF_BOARD);
    }
  }
}
```
