# Bubble Breaker Rewrite — Implementation Roadmap

**Spec:** [2026-09-27-bubble-breaker-rewrite-design.md](../specs/2026-09-27-bubble-breaker-rewrite-design.md)

The spec covers separate subsystems: game engine, app, CI/CD and deployment. The work is therefore split into sequential sub-plans.
- Each sub-plan produces working, tested software and ends with a merge to `main`.
- Each sub-plan is written in full detail **only after the previous one is merged**, so it builds on the real code and APIs rather than on guesses.
- Plans 01 and 02 are written now: they depend only on the spec.

| # | Plan | Delivers | Spec milestone | Status |
|---|---|---|---|---|
| 01 | [Skeleton & CI](2026-09-27-01-skeleton-and-ci.md) | Angular 22 workspace, strict TS, lint/format/hooks, Vitest + coverage gates, app shell with tokens + font, CI (`quality`, `build`), CodeQL, Dependabot, public repo, `main` + ruleset | 1 | done |
| 02 | [Engine](2026-09-27-02-engine.md) | Pure TS rules engine: rng, board, groups, physics, burst, game over; unit + property tests (≥ 95 %) | 2 | done |
| 03 | [State & platform](2026-10-28-03-state-and-platform.md) | GameStore, StatsStore, SettingsStore, PhaseRunner, timer, persistence (`bb:v1:*`) with guards, ports (Storage, Clock, Audio, Visibility, ReducedMotion) + fakes (≥ 90 %) | 3 | done |
| 04 | Board UI | Layout math, balls, highlight, points bubble, focus cursor, live region, pointer + keyboard input, animations | 4 | next — write plan |
| 05 | Chrome & screens | Title bar, status strip, softkeys, popup menu, dialog, toast; routes for Scoring, Statistics, Options, How to Play, About; Paused | 5 | after 04 |

| 08 | E2E & polish | Playwright (seeded games, reload, offline), axe, visual baselines, Lighthouse CI, manual device checks, README/About | 9 | after 07 |

The required status checks on `main` grow with the plans:
- **01:** `quality`, `build`, `pr-title`, CodeQL.
- **07:** adds `docker`.
- **08:** adds `e2e` and `lighthouse`.

## Working agreement

- **Branches:** every plan runs on a feature branch off `main` (e.g. `feat/skeleton`, `feat/engine`) and is merged by PR.
- **Cloud sessions:** plans can run in Claude Code on the web. `.claude/hooks/cloud-setup.sh` provides Node ≥ 24.15. Known limits there (seen in Plan 01):
  - The superpowers plugin does not load. Run one implementer subagent per task and review each task before the next.
  - `gh` has no valid token. Open the PR and poll its check runs with the GitHub connector; fix failures before stopping.
  - `rsync` is missing; use a `tar` pipe.
  - Steps that need GitHub admin rights (repo settings, rulesets) and the final merge run locally.
- **Commits:** Conventional Commits, small and frequent, following the steps in each plan.
- **Deviations:** if implementation contradicts a phase doc, update the doc (or add an ADR) in the same PR, per DoD item 1 ([04-quality.md](../../04-quality.md)).
- **Obsidian copy:** after merging doc changes, refresh the vault copy with the rsync command in the planning [README](../../README.md#using-these-docs-in-obsidian).
