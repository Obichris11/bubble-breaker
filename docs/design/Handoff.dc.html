1 · Layout
The screen is a vertical flex column: title bar (26px), status strip (30px), board area (flex: 1, white) and softkey bar (44px touch, 32px with pointer: fine). The chrome never scales, only the board does.
avail_w = viewport_w − 2 × 4px
avail_h = viewport_h − 26 − 30 − softkey_h − 4 (board bottom pad) − safe-area insets
cell    = floor( min( avail_w / 11, avail_h / 12, cell_max ) )   // cell_max 72 touch, 48 desktop
board  = 11·cell × 12·cell, centered horizontally, bottom-aligned in the board area

cell 32px, board 352×384, 148px free above the board

768×1024
cell 69px, board 759×828
Desktop
centered app window sized to the board (cell 48px gives 536×692), bevelled frame, #2F6468 backdrop. If the viewport height is under 700px, recompute the cell from the height.
Always round the cell down to whole pixels so balls sit on integer positions. Use 100dvh and env(safe-area-inset-*), and recompute on resize (ResizeObserver on the board area). The board is bottom-aligned because balls fall downward: the bottom row stays in thumb reach and the space that clears opens up above. PWA notices use that free space at the top.
2 · Interaction
One pointer handler on the board. Compute col = floor(x / cell) and row = floor(y / cell). The whole square cell is the hit area (including the gaps and corners around the circle), so there are no dead zones between balls.
Keeping small balls forgiving. At 32px a single cell is below 44px, but no action ever needs a precise tap on one ball. The first tap only previews, which is harmless. The confirming tap is accepted anywhere on the highlighted group, and a group always has at least 2 cells, so it is 64px or more along one axis. A mis-tap only moves or clears the highlight and never bursts anything. Use touch-action: manipulation so there is no double-tap zoom delay.
States. Tapping a group of 2 or more selects it and shows the bubble. Tapping the same group again bursts it. Tapping another group moves the selection. Tapping a lone ball, an empty cell or outside the board clears it. Input is ignored during pop, fall and slide.
Burst sequence. Pop the group. Apply gravity per column. Close empty columns to the right, so empty space collects on the left. Then check for game over: if no two orthogonal neighbours share a colour, wait 500ms and open Scoring.
Points bubble. Anchored above the tapped ball, or below it when the ball is in the top row. Its centre is clamped 34px from the board edges. The bubble never intercepts input (pointer-events: none). The "Selected" field repeats the value.
Pause. The timer stops while the Menu, any screen or a dialog is open, and while the page is hidden. On visibilitychange → hidden the game enters the Paused state and needs Resume. Save the board and elapsed time to storage on every burst and on pause.
Softkeys. On the game screen: New Game (left) and Menu (right). On other screens: Done (left, returns to the game) and Menu (right). New Game during a game that is under way does not ask for confirmation, as in the original. The abandoned game is not counted in the statistics.
PWA. Show "New version" when the service worker reports an update. Reload only when the player taps it, and save the game first. Show "Offline ready" once, on the first successful cache, and hide it after 4s. Offer Install only after the first finished game, and only when beforeinstallprompt is available. "Not now" suppresses it for 30 days.

Animate only transform and opacity. Every ball is an absolutely positioned element keyed by a stable ball id (use trackBy in Angular) and placed with translate(col·cell, row·cell). Changing the transform with the right transition set produces the fall and slide animations. Never re-create ball elements between phases, or the animation is lost. Wait for each phase with a timer (or transitionend on one ball) before starting the next. Menus appear instantly, as they did on the original device.
4 · Accessibility (WCAG 2.2 AA)
Contrast. Black on #D4D0C8 is 13.6:1. White title text is at least 4.9:1 across the #0A246A→#3A6EA5 gradient. #404040 muted text is 10.4:1 on white. The group highlight #7486C4 is 3.2:1 against white (1.4.11), and #8C8C8C is 3.4:1 in greyscale. Bevel edges (#404040/#808080 on #D4D0C8) keep controls identifiable at 3:1 or more.
Keyboard. The board is one focusable element (tabindex="0") that manages its own cursor. Arrow keys move the cursor (it moves onto empty cells too and never wraps). Enter or Space selects, and again bursts. Esc clears the selection or closes the menu. N starts a new game and M opens the menu. The focus ring is 2px black with a 1px white keyline on both sides and shows only for keyboard input (:focus-visible behaviour). Chrome buttons use a 1px dotted focus rectangle. Menus support arrow keys, Home/End and Esc, and return focus to the Menu softkey. Dialogs trap focus, start on the safe button (Cancel) and close with Esc.
Screen readers. The board has role="application" and an aria-label with the key help. A polite live region announces the cursor cell ("Row 4, column 7, blue, group of 6"), the selection ("6 blue balls selected, 30 points. Press Enter again to burst."), the burst result ("+30, score 1,234") and game over. The status fields are plain text.
Colour is never the only cue. Selection is shown by a cell background with 3:1 contrast plus the bubble plus the live region. The Greyscale set differs by pattern (diagonal, solid, dotted, banded, checkered) and also by lightness. Colorful Breakers can show optional shape hints (▲ ● ■ ◆ ✚), which are off by default so idle balls match the reference.
Targets. Softkeys, buttons and option rows are at least 44px high on touch. Menu rows are 40px high × 184px wide, which exceeds the 24px minimum in 2.5.8 and is traded for density.
5 · Ball rendering recipe
.cell { width: var(--cell); height: var(--cell); display: grid; place-items: center; }
.ball {
  width: 95%; height: 95%; border-radius: 50%;
  background:
    radial-gradient(circle at 30% 28%, rgba(255,255,255,.95) 0%, rgba(255,255,255,.55) 5%, rgba(255,255,255,0) 11%),
    radial-gradient(circle farthest-side at 35% 30%, var(--hi) 0%, var(--body) 40%, var(--edge) 100%);
}
farthest-side is required. With the default farthest-corner the gradient ends at the corner of the box, outside the circle, and the lower-right edge never gets dark. With farthest-side the radius is 70% of the diameter, so the edge colour lands on the lower-right rim. Greyscale balls add two layers between the specular layer and the shading: an edge-darkening overlay and a pattern (see tokens.css, .bb-ball--g1…g5). Pattern sizes are in %, so they scale with the ball.
6 · Dark theme
Skip it. The light grey chrome and white board are the look, and a dark version would be a new design rather than a variant. A dark board would also break the reference: the dark ball edges need white behind them to read as spheres. If a dark mode is ever needed, darken only the desktop backdrop and leave the app window as it is.
7 · Do not get these wrong
1. Empty columns close to the right. Empty space collects on the left.
2. Groups use 4-neighbour adjacency only, never diagonals. A single ball is never a group.
3. Score is n × (n − 1) per burst. There is no end bonus, and time is not scored.
4. Never change the idle ball rendering for highlight, focus or burst. Those cues go behind the ball or around it.
5. No outlines, drop shadows or reflections on the balls, and no grid lines. The board is pure #FFFFFF.
6. Keep ball DOM nodes stable (trackBy id). Move them with transform and never with top/left.
7. Game over opens Scoring automatically, and the finished game is added to the statistics exactly once.
8. Integer cell sizes. Recompute on resize and orientation change.
9. Don't ship proprietary fonts or logos. Use Noto Sans (OFL) and self-host it for offline use.
8 · Tokens
All values are in tokens.css: chrome colours, bevel shadows, the 3 stops for each ball colour, the greyscale stops and patterns, the ball recipe classes, ball ratio, board background, font stack, spacing, radii, z-index, motion durations and easings, plus overrides for pointer: fine and prefers-reduced-motion.
